# Engineering Operating System (EOS) v1.0

**Project:** Amar Smart Doctor

**Version:** 1.0

**Status:** Approved

**Owner:** CTO

---

# 1. Purpose

The Engineering Operating System (EOS) defines how Amar Smart Doctor is designed, built, reviewed, documented, and maintained.

It is the governing framework for every engineering decision.

The purpose of EOS is to ensure that every contributor—human or AI—works using the same principles, responsibilities, and workflows.

EOS exists to reduce ambiguity, prevent knowledge fragmentation, and create a maintainable engineering organization.

---

# 2. Vision

Amar Smart Doctor is not simply a software product.

It is an AI-native healthcare knowledge platform.

Knowledge is the primary asset.

Software exists to organize, deliver, verify, and improve knowledge.

Every engineering decision must strengthen this vision.

---

# 3. Engineering Principles

## Principle 1

Knowledge Before Code

Understanding the problem always comes before implementation.

No feature should be developed without first documenting its purpose.

---

## Principle 2

Architecture Before Implementation

Systems are designed before they are built.

Engineering decisions should not be made while writing code.

---

## Principle 3

Documentation Evolves With Engineering

Documentation is not an afterthought.

Engineering work is incomplete until documentation reflects reality.

---

## Principle 4

Simple Over Clever

Prefer maintainable solutions over complex ones.

Complexity must always justify itself.

---

## Principle 5

Long-Term Thinking

Every decision should optimize the platform for years, not weeks.

---

# 4. AI Philosophy

Artificial Intelligence accelerates engineering.

Artificial Intelligence does not replace engineering judgment.

AI assists with:

- research
- planning
- implementation
- automation
- documentation
- testing

Human approval remains mandatory for critical decisions.

---

# 5. Human Responsibilities

The project owner remains accountable for:

- business decisions
- product vision
- medical validation
- legal responsibility
- production approval

Responsibility cannot be delegated.

---

# 6. AI Responsibilities

# 8. Single Source of Truth

Knowledge is the source of truth.

ASM Brain represents the human-readable knowledge system.

Git preserves its history.

GitHub synchronizes collaboration.

No duplicate sources of truth should exist.

---

# 9. Single Writer Principle

Every artifact has exactly one primary writer.

Examples:

Architecture → ChatGPT

Implementation → Google Antigravity

Medical Validation → Human Experts

Knowledge Review → Human + ChatGPT

Source Code → Antigravity

This prevents conflicting ownership.

---

# 10. Decision Process

Every significant engineering decision follows this sequence.

1. Understand the problem.

2. Evaluate alternatives.

3. Document reasoning.

4. Review risks.

5. Approve the decision.

6. Implement.

7. Verify.

8. Update documentation.

No steps should be skipped.
